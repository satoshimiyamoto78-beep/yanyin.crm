## 1. Дерево системы

```

├── 🟡 Владелец платформы (основатель) ............ yanyin.core
│   ├── Заведения-клиенты: карточка, онбординг, вход в аккаунт для поддержки
│   ├── Подписки и биллинг: тарифы, счета, промокоды, пробный период, MRR/ARR, комиссии с платежей
│   ├── Глобальная аналитика: активные заведения, GMV, отток, удержание, рост
│   ├── Контроль AI: расход токенов по заведениям, стоимость, лимиты, качество ответов Yan
│   ├── Глобальные библиотеки: рецепты, шаблоны меню, шаблоны квестов, бейджи
│   ├── Функции и релизы: feature flags по тарифу или заведению
│   ├── Поддержка: тикеты, чат, база знаний
│   ├── Интеграции и партнёры: платежи, фискализация, POS, доставка
│   ├── Безопасность: журнал действий, роли команды платформы

├── 🔵 Владелец заведения / менеджер ................ yanyin.hq
│   ├── Главный дашборд, филиалы
│   ├── Меню: категории, позиции, модификаторы, фильтры, стоп-лист, расписание
│   ├── Склад: остатки, приход, списание по техкартам, инвентаризация, поставщики, сроки, отходы
│   ├── Рецепты и техкарты: ингредиенты, граммовки, выход, себестоимость

│   ├── Аналитика: menu engineering, прогноз спроса, смены
│   └── AI Yan для менеджера: вопросы обычным языком, утренний отчёт, советы
├── 🟣 Персонал ..................................... yanyin.crew
│   ├── Официант: столы, вызовы, счёт, подсказки для апсейла
│   ├── Повар / бармен: техкарты с фото и видео
│   ├── Личная страница: доход, KPI, цели до бонуса
│   ├── Квест-доска, XP, уровни, бейджи, kudos
│   └── Смены: график, отметка по QR
├── 🟠 Кухня и бар .................................. yanyin.kitchen
│   └── Очередь заказов в реальном времени, статусы, таймеры, стоп-лист одной кнопкой
├── 🔴 Гость ........................................ yanyin.menu
│   ├── Меню по QR: фото, фильтры, аллергены, перевод
│   ├── Игры: Food Roulette, Mystery Dish, Table Battle, Taste Quiz, скретч-карта
│   ├── Заказ и оплата: общий счёт, сплит, чаевые, вызов официанта
```

## 2. Уровни доступа (multi-tenancy)

| Уровень | Поверхность | Что видит |
|---|---|---|
| Платформа | yanyin.core | Все заведения, все данные, тарифы, биллинг, настройки системы |
| Организация (тенант) | yanyin.hq | Только своя организация и её филиалы |
| Филиал | yanyin.hq (менеджер филиала), yanyin.kitchen | Только свой филиал |
| Сотрудник | yanyin.crew | Свои заказы, свой доход, свои квесты |
| Гость | yanyin.menu | Публичное меню и свой профиль лояльности |

Иерархия данных: **Platform → Organization (тенант, юрлицо) → Location (филиал) → Table / Staff / Stock**.
Изоляция обеспечивается через Postgres Row Level Security по `organization_id` (подробнее в `.claude/skills/yanyin-product/references/engineering.md`).

## 3. Цепочки процессов

### Путь заказа
1. Гость сканирует QR на столе → открывается yanyin.menu (без установки)
2. Выбор: фильтры, совет Yan или Food Roulette
3. Заказ: API проверяет стоп-лист и сохраняет заказ
4. Кухня (KDS) и телефон официанта получают заказ в реальном времени
5. Статусы: принят → готовится → готов → выдан
6. Оплата: с телефона гостя или через официанта; сплит, чаевые
7. **Фискализация:** чек уходит через провайдера виртуальной кассы в ОФД
8. Склад списывает продукты по техкарте, а при низком остатке появляется алерт или автозаказ
9. Финансы: выручка, себестоимость, маржа блюда
10. Персонал: KPI, прогресс квестов, XP, чаевые
11. Гость: баллы в yanyin.club, просьба оставить отзыв
12. AI Yan готовит утренний отчёт для владельца
13. Агрегаты (GMV, активность, расход AI) видны в yanyin.core

### Цикл квеста
1. Менеджер создаёт квест: условие (метрика + цель), срок, награда, тип (соло / команда / соревнование)
2. Квест появляется на доске и приходит уведомление нужным ролям
3. Сотрудник берёт квест
4. Прогресс считается **автоматически из событий системы** (заказы, отзывы, списания)
5. Выполнение: анимация, XP, бейдж, лидерборд
6. Награда уходит в расчёт зарплаты и в финансы

### Подключение заведения
1. Регистрация, выбор тарифа, пробный период
2. Онбординг: импорт меню (фото, Excel, AI-распознавание), шаблоны техкарт и квестов
3. Приглашение команды и назначение ролей
4. QR-коды на столах
5. Подключение платежей и фискализации
6. Оплата подписки (MRR)
7. Основатель видит рост, активность и тикеты в yanyin.core

## 4. Технологический стек

| Слой | Выбор | Зачем |
|---|---|---|
| Язык | TypeScript | Один язык на фронте и бэке |
| Веб | Next.js (App Router), React | Все поверхности |
| UI | Tailwind CSS, shadcn/ui, Framer Motion | Быстро, современно, анимации игр |
| Приложения | PWA (menu, crew, kitchen), веб (hq, core) | Без установки, работает на старых Android |
| Мобильные | React Native / Expo | Позже |
| БД | PostgreSQL (Supabase) | Основная база, RLS для тенантов |
| Realtime | Supabase Realtime (WebSockets) | Кухня, официанты, живой зал |
| Кэш / очереди | Redis (Upstash) | Позже, по мере нагрузки |
| Аналитика | Postgres → ClickHouse / Tinybird | ClickHouse при масштабе |
| AI | Claude API, pgvector | Yan, поиск по меню и рецептам |
| Платежи | Адаптеры: Payme, Click, Uzum, Alif, Корти Милли / нац. QR, Stripe | Локальные рынки |
| Фискализация | Адаптеры виртуальных касс / ОФД (UZ, TJ) | Обязательно по закону |
| Хостинг | Vercel + Supabase | Минимум DevOps на старте |
| Мониторинг | Sentry, логи Vercel | Ошибки и производительность |
| CI/CD | GitHub Actions | Тесты, линт, миграции |

## 5. Планируемая структура монорепозитория

```
yanyin.crm/
├── apps/
│   ├── web/            # Next.js: hq, core, crew, kitchen, menu (route groups по поверхностям)
│   └── mobile/         # позже: Expo
├── packages/
│   ├── db/             # схема, миграции Supabase, сгенерированные типы, RLS-политики, сиды
│   ├── domain/         # чистая бизнес-логика: food cost, списания, квесты, лояльность (без I/O, 100% тесты)
│   ├── ui/             # дизайн-система: токены, компоненты shadcn
│   ├── ai/             # Yan: промпты, инструменты, ограничения расходов
│   ├── payments/       # адаптеры платёжных провайдеров
│   ├── fiscal/         # адаптеры фискализации
│   └── i18n/           # ru, uz, tg, en
├── supabase/           # конфиг, миграции, edge functions
├── docs/
└── .claude/skills/     # проектные скиллы
```

Поверхности живут в одном Next.js-приложении как route groups: `(core)`, `(hq)`, `(crew)`, `(kitchen)`, `(menu)`. Их можно отдавать на разных поддоменах через middleware (`hq.yanyin.app`, `menu.yanyin.app/{venue}`). Если какой-то поверхности понадобится отдельный деплой, её легко вынести.

## 6. Ключевые сущности

Platform: `organizations`, `subscriptions`, `plans`, `invoices`, `feature_flags`, `ai_usage`, `audit_log`, `support_tickets`.
Venue: `locations`, `tables`, `floors`, `menus`, `categories`, `menu_items`, `modifiers`, `modifier_groups`, `item_schedules`.
Stock: `ingredients`, `units`, `recipes` (техкарты), `recipe_lines`, `stock_items`, `stock_movements`, `suppliers`, `purchase_orders`, `inventory_counts`, `waste_log`.
Orders: `orders`, `order_items`, `order_item_modifiers`, `payments`, `fiscal_receipts`, `tips`, `discounts`, `voids`.
People: `users`, `memberships` (user × organization × role), `staff_profiles`, `shifts`, `time_clock`, `payroll_items`.
Game: `quests`, `quest_participants`, `quest_progress`, `xp_ledger`, `badges`, `badge_awards`, `kudos`.
Guests: `guests`, `loyalty_accounts`, `loyalty_ledger`, `campaigns`, `reviews`.
Events: `domain_events` (append-only журнал: от него считаются квесты, аналитика и AI-отчёты).
